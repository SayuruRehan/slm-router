# Appendix B. Detailed Project Risk Register

**Purpose:** Supporting detail for TRACER-125.

| ID | Risk | Likelihood | Impact | Trigger / Early warning | Owner | Preventive mitigation | Contingency |
|---|---|---|---|---|---|---|---|
| R1 | Objective validators contain incorrect/incomplete tests | Medium | High | Reference fails, buggy fixture passes, unexplained disagreements | Lithma + Sulakna | Sanity gates; independent fixture review; compare execution with static/manual evidence | Exclude affected fixture, repair validator, version a new validator release |
| R2 | Generated code escapes or abuses execution environment | Low–Medium | Critical | Unexpected file/network/process behaviour | Sayuru | Docker network none; resource caps; read-only FS; cap-drop; no-new-privileges | Stop execution, quarantine artefact, harden sandbox before rerun |
| R3 | GPT-4.1/API version or behaviour changes mid-run | Medium | High | Model identifier changes, sudden outcome/latency shift | Sayuru | Record model/date/settings; execute primary action run in a bounded window | Split/report runs by model version or rerun affected portion consistently |
| R4 | Local SLM inference is not reproducible across machines | Medium | Medium–High | Different outputs under same manifest | Sayuru | Freeze model revision, prompt, decoding controls, environment/container where possible | Treat backend as an experimental factor and rerun on one canonical environment |
| R5 | ACRE feature leakage from gold/reference/action outcomes | Low–Medium | Critical | Feature references benchmark target or post-action fields | Entire team | Explicit allowed/forbidden schema; code review; leakage unit tests | Remove leaked features, invalidate affected model/evaluation, retrain |
| R6 | ACRE overfits training data | Medium | High | Large train-test gap or unstable calibration | Sayuru | Grouped 60/20/20 split; simple baselines; regularisation; held-out test untouched | Simplify model, reduce features, report limitation |
| R7 | Action outcomes are too imbalanced for reliable heads | Medium | Medium–High | One action nearly always succeeds/fails | Sayuru | Inspect prevalence before training; class-aware metrics; stratified/domain analysis | Use weighted loss/sampling only if pre-specified and document sensitivity |
| R8 | REPAIR/REGENERATE comparison is confounded by prompt/settings differences | Medium | High | One action has different temperature/model/version/retry policy | Entire team | Same stronger-model version; frozen prompts and generation controls | Rerun affected action outcomes with matched controls |
| R9 | Action-outcome generation exceeds time/API budget | Medium | High | Throughput pilot predicts missed Sep 20 milestone | Sayuru | Pilot throughput; checkpointed batches; mandatory domains first | Reduce optional TAT-QA/transfer scale before reducing primary study validity |
| R10 | Manual unresolved-label review lacks independent reliability | Medium | Medium | Many validator-unresolved cases | Entire team | Prioritise objective validators; define dual-review/adjudication for final study | Report unresolved subset separately; exclude uncertain labels rather than force binary |
| R11 | Novelty claim becomes inaccurate as literature changes | Low–Medium | Medium | New close work appears before submission/thesis | Lithma | Evidence-bounded wording; final literature search at proposal/thesis gates | Update gap/positioning rather than defend obsolete absolute claim |
| R12 | Cross-SLM transfer is poor | Medium | Medium | Large calibration/discrimination drop on Gemma | Sayuru | Separate transfer evaluation; model-ID/domain features only if pre-specified | Report transfer limitation; do not pool with primary result |
| R13 | Team review bottlenecks delay merge/approval | Medium | Medium | PRs/tasks wait > one sprint for review | Entire team | Assign reviewer at task start; small PRs; weekly review | Reallocate review ownership at sprint planning |
| R14 | Proposal/thesis claims drift from code/results | Medium | High | Metrics/names differ between docs and repo | Entire team | Frozen terminology; source every number from versioned artefact | Correct narrative before submission; include final claim/evidence audit |
